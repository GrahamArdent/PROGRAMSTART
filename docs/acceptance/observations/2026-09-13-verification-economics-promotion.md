## Real evidence

PROGRAMSTART issue #107 began as a real cost/amplification defect, not a speculative optimization: autonomous repository work was repeatedly fanning small corrections into multiple hosted GitHub Actions jobs, including specialized acceptance surfaces whose prior evidence had not been invalidated.

The candidate rule was exercised through four owner-specific pilots before methodology promotion:

- Autonomous Controller — draft/ready hosted-acceptance behavior, specialized evidence reuse and reduced unrelated fanout;
- Compute Spine — draft/ready behavior, concurrency/invalidation scoping and a Challenge correction for a transitive Ansible dependency invalidator;
- Mission-Control — draft/ready acceptance with unsupported cache optimization rejected by Challenge;
- GCRM — existing marker-driven checkpoints retained while scheduled regression cadence was reduced using observed evidence and manual/event-driven escape hatches.

The original methodology PR #108 passed its then-current PR Validation but became stale/non-mergeable as PROGRAMSTART `main` advanced. The lesson was therefore re-recovered against current authority rather than forcing an old-base merge.

Current-base PR #110 (`learning/ci-verification-economics-reconcile`) passed exact-head PR Validation at `105fae294882f3cb846202e0cab9a7cb597a9bc1` and merged as `35ed62358b1ebd72c18002ed24a8fd0391884beb`.

## Implemented rule

`docs/PROGRAMSTART_VERIFICATION_ECONOMICS.md` now owns the operational protocol:

> **Validate cheaply while iterating; spend independent hosted verification only when evidence was invalidated or a meaningful acceptance boundary is reached.**

The protocol composes with existing Cost Governance, Work Packet evidence reuse/invalidation and the Challenge Gate. It does not create a CI platform, testing service, scheduler, queue, evidence authority or permission to weaken consequential verification.

## Challenge result

The methodology delta survived the current-authority Challenge with these boundaries intact:

1. cost reduction comes from eliminating redundant work, not skipping actually invalidated proof;
2. owner-specific pilots remain evidence, not universal workflow templates;
3. draft/ready behavior requires a machine-readable acceptance transition and explicit `ready_for_review` handling where GitHub PR lifecycle is used;
4. path/invalidation filters must include transitive dependencies and workflow/config changes;
5. exact-head hosted acceptance remains independent evidence when the owner requires it;
6. provider/runner failures are evidence to classify, not bypass permission;
7. a self-hosted privileged runner is not automatically justified by hosted-CI cost;
8. post-merge reuse is allowed only when the merge does not materially change the accepted artifact/integration surface.

## Learning Gate

This behavior is materially distinct from generic Cost Governance (`PSL-014`) and generic post-implementation Challenge (`PSL-015`): it governs the **economics and invalidation lifecycle of verification itself** across autonomous iteration and acceptance boundaries.

A dedicated rollup lesson is therefore earned.

**Maturity:** `implemented`

It is not yet `validated` as generic methodology merely because the four pilots preceded promotion. Validation requires a natural project to consume the now-current PROGRAMSTART protocol and demonstrate that:

- redundant hosted work is avoided during iteration;
- still-valid evidence is actually reused;
- an invalidating change still triggers the required specialized/independent proof;
- no release/consequence gate is weakened;
- the project can explain why the selected verification tier is sufficient.
