# PROGRAMSTART Learning Observation — Canonical Producer Invocation

Date: 2026-09-27
Source: Controller #170/#171 live acceptance
Disposition: **STRENGTHEN_EXISTING_LESSONS (`PSL-021`, `PSL-023`)**

## Observation

The Controller #170/#171 acceptance case showed that a known/proven receiver or operational path is not sufficiently actionable when the consequence producer must still synthesize transport ad hoc. Live proof of the fixed Windows `/v1/programstart-objective` helper supplied the missing bounded producer invocation: an accepted current mechanism, source, and principal for the already-authorized consequence.

Effective Autonomy must therefore resolve that producer-ready invocation from current owner/path evidence before acting. If the receiver exists but no bounded invocation is available, the condition remains `temporary_automation_gap` and must be repaired or routed to its owner, not improvised through transport or a human/chat relay.

This strengthens the existing alternative-actuation (`PSL-021`) and operational-path readiness (`PSL-023`) lessons. It creates no new lesson, global path registry, mandatory fallback, or second orchestrator. Actual path/invocation inventory and currentness remain with Path Authority or the owning project.
