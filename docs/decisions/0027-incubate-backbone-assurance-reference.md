# 0027. Incubate the Backbone Assurance Reference with Owner-Local Repairs

## Context and Problem Statement

The operator requested a durable audit of the backbone, immediate repair of demonstrated Paths test gaps, Git retention alongside that work, and evidence of maintenance/ownership need before creating a separate repository. Existing Lab, Evidence Spine, Matrix and component responsibilities overlap with pieces of this concern. Another repository does not establish independent verification.

## Decision Drivers

- Deliver the demonstrated regression protections immediately.
- Retain research, four linked views, source identities, evidence gaps and correction status.
- Preserve owner-local implementation, experimental and acceptance responsibilities.
- Avoid another service, scheduler, live-state inventory or strategic execution spine.

## Considered Options

1. Create a separate repository immediately.
2. Put methodology and owner acceptance in Ecosystem Lab.
3. Keep only external document/workbook snapshots.
4. Incubate this bounded reference under PROGRAMSTART with owner-local repairs.

## Decision Outcome

Chosen option: **4**, explicitly selected by the operator for this audit. `backbone-assurance/` is a non-authoritative cross-project reference. Component tests/fixes remain in their owning repositories; accepted evidence and experiments retain their existing owners. Generated repositories inherit this decision as provenance, not a copied audit register or a requirement to create one. This is not a general central packet archive and does not supersede ADR-0026's owner-routing policy. The Library foundation becomes a historical snapshot and handoff pointer, while the Git register is the editable source.

Extract only when demonstrated independent maintenance, access requirements, harness release cadence or measured coordination cost justifies the move. Record destination ownership, migration and rollback first. Importance or file count alone does not qualify.

### Consequences

- Good: one reviewable audit entry point without new runtime infrastructure.
- Good: the Paths regression repair remains with the code it protects.
- Bad: incubation requires discipline to prevent reference data becoming shadow acceptance or stale duplicate live state.
- Neutral: source publication is not merge, hosted qualification, installed adoption or owner acceptance.

## Confirmation

The audit's schema/retention negative controls and generated views must agree. Paths correction evidence must be linked by exact source identity. Repository-wide gate failures must be retained, not hidden or waived. Any separate repository must earn a new decision through observed ownership and maintenance need.
