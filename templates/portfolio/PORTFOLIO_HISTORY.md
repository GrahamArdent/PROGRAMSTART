# Portfolio Attention History

> Record only meaningful operator-attention transitions. Do not mirror repository commits, PRs, project game plans, or the PROGRAMSTART learning ledger.

| Date/time | Project | Previous attention | New attention | Reason / evidence | Revisit or handoff |
|---|---|---|---|---|---|
| `<timestamp>` | `<project>` | `<class>` | `<class>` | `<why the attention decision materially changed>` | `<authority / trigger>` |

## Record a transition when

- a project becomes or stops being the primary build;
- a short operator gate becomes current, completes, or is superseded;
- a dependency materially changes attention priority;
- a project is deliberately parked or brought back into consideration;
- live verification corrects a stale portfolio assumption.

## Do not record

- every commit or PR;
- ordinary status refreshes with no attention impact;
- project-internal milestone details already owned by project authority;
- captured ideas that have not been promoted into real project authority;
- methodology lessons that belong in the PROGRAMSTART Learning Loop.
